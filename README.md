# 온(ON)마을 복(福) 터졌네! — 한가위 주사위 골든벨

- 송출: https://chuseok-eight.vercel.app/game
- 담당자: https://chuseok-eight.vercel.app/admin

## 행사 진행

담당자 로그인 → 조작권 이어받기 → 게임 시작 → 실물 주사위 결과 1~6 입력 → 주사위 공개 → 한 칸씩 이동 → 도착 안내.
**문제 열기**는 담당자가 누릅니다. 제한시간 종료 후에도 **정답판 안내**와 **정답 공개**를 각각 수동으로 누릅니다. 정답/미션 성공 판정은 시트의 해당 문제 점수를 한 번만 지급합니다. 판정 후 다음 팀으로 자동 전환합니다. 진행 중에는 일시정지·계속 진행·이전/다음 단계·위치/점수 수정이 가능합니다.

최종 발표 준비 → 강사님 노래 메들리 안내 → 담당자가 **최종 점수 공개** → 합산 점수가 가장 높은 팀 MVP. 동점은 공동 MVP입니다. 성공 8회 조건은 사용하지 않습니다.

### 현재 진행 규칙 확인 사항

현재 GitHub main은 총 진행 횟수 방식(기본 29회)입니다. **팀당 7턴·세 팀 모두 4턴 완료 후 중간집계는 현재 main에 포함되지 않았습니다.** 별도 미완성 festival 작업을 이번 음향 수정으로 덮어씌우지 않았습니다. 해당 기능은 별도 병합·검증이 필요합니다. 이번 수정은 기존 진행 규칙과 저장된 점수·위치를 변경하지 않습니다.

## 문제은행

기존 Google Sheets 또는 Apps Script 주소를 사용합니다. 조작권이 있는 관리자 창은 5초마다, 게임 시작과 문제를 열기 전 최신 문제은행을 확인합니다. 칸번호로 매칭하므로 시트 행 순서와 무관하게 1~29번 칸을 유지합니다. 실패 시 마지막 데이터를 사용합니다. 이미 판정한 문제의 점수는 새로 불러오기로 소급 변경하지 않습니다.

열: 칸번호 / 유형 / 제목 / 문제 / 보기1 / 보기2 / 보기3 / 보기4 / 정답 / 미션내용 / 제한시간 / 사용여부 / 점수(또는 배점).
객관식은 보기 2~4개와 정답, 주관식은 문제와 정답, 미션은 미션내용을 입력합니다. 시트의 점수가 우선합니다. 배점이 비어 있을 때만 유형별 기본값을 사용합니다.

## 방송 BGM과 성공 효과음

- **방송 음향**: BGM ON/OFF, 음량 슬라이더(기본 12%) → **음량 적용**, 성공음 테스트. 설정은 기존 Supabase 상태로 동기화됩니다.
- 송출 /game의 소리 켜기 버튼으로 재생합니다. 관리자 창을 공유할 때는 방송 음향의 이 관리자 창에서 소리 켜기를 누릅니다.
- 브라우저 정책 때문에 **송출 컴퓨터에서 화면 아무 곳이나 최초 한 번 클릭**해야 합니다. 다른 컴퓨터의 관리자 클릭으로 이 제한을 해제할 수 없습니다. 새로고침 후에는 다시 클릭하세요.
- 화상회의로 송출할 때 **탭 오디오 공유 / 시스템 소리 공유**도 켜세요. 이 설정은 게임에서 대신 켤 수 없습니다.
- BGM ON이면 해당 창에서 소리를 활성화한 뒤 게임 시작 전에도 반복하며 일시정지 시 멈춥니다. 메들리 중에는 담당자가 BGM을 OFF로 바꿀 수 있습니다.
- 성공음 재생 중 BGM은 설정 음량의 20%로 낮아지고 종료 시 복귀합니다. 동일 이벤트·오래된 이벤트·재접속 당시 이벤트는 반복 재생하지 않습니다.
- [음원 출처·이용조건](public/audio/LICENSES.md): **How are you 가야금**(서예지, 공유마당, 기증저작물 자유이용), **Correct Bell**(Fupi, CC0). 원본 파일을 프로젝트 내부에 저장했습니다. 출처 표기는 계속 유지하세요.

## 다른 컴퓨터 / 개발 / 배포

행사 운영은 위 링크만 열면 됩니다. 송출은 로그인 없이 읽기만 가능하며 관리자만 수정합니다. 행사 중 담당자 창 하나는 조작권을 유지한 채 열어두세요.

소스 수정은 Node.js 22 이상 설치 후:

```sh
git clone https://github.com/qlcdywjd20-max/chuseok.git
cd chuseok
npm install
```

`.env.example`을 `.env.local`로 복사하고 기존 Supabase의 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`를 입력합니다. secret/service_role 키나 비밀번호는 넣지 마세요. `.env.local`은 Git에서 제외됩니다.

```sh
npm run dev
npm test
npm run build
```

Vercel: 저장소 Import → Framework Other → Build `npm run build` → Output `dist` → 같은 두 환경변수 설정 → Deploy. 기존 연결 프로젝트는 main 변경 시 자동 배포됩니다. `public`의 음원도 `dist`로 복사합니다.

새 Supabase 프로젝트에 처음 설치할 때만 `supabase.sql`을 실행하고 Auth 사용자를 만든 뒤 관리자 allowlist에 등록하세요. 기존 프로젝트의 테이블·Auth·RLS·실시간 연결은 그대로 사용합니다.

## 수정 파일과 검증

- `audio.js`: 로컬 파일 재생, 중복 방지, 음량 낮춤/복귀, 최초 클릭 활성화
- `app.js`: 성공 이벤트, BGM 설정, 배점 배지 연결
- `index.html`: 큰 금색 배점 배지와 음원 표기
- `build.cjs`, `dev.cjs`: 음원 배포/로컬 제공
- `public/audio`: MP3, WAV, 이용조건
- `audio-test.cjs`, `presentation-test.cjs`, `test.cjs`, `package.json`: 음향과 기존 수동 진행 회귀 검증

실제 Chromium에서 BGM 58.032초 파일의 재생 시간 증가와 반복, 성공음 1.598초 파일 재생, 동일 이벤트 1회 재생을 확인했습니다. 음량 12%→2.4%→12% 복귀, 음소거·재개, 파일 오류 대체는 자동 테스트로 확인했습니다. 현장 스피커 출력과 화상회의 상대방에게 전달되는 소리는 행사 장비에서 최종 확인하세요.

기존 Sheets 갱신·칸번호 매칭·오프라인 예비 동작·수동 정답판/정답 공개·MVP·주사위 이동·점수 중복 방지·PostgreSQL RLS 테스트를 통과했습니다. LIVE/50개소 표시는 행사 브랜딩이며 실제 화상회의 접속 수 측정값이 아닙니다.


### 송출 소리가 안 날 때 (재생 상태 표시)

관리자 창을 공유하는 경우 **이 관리자 창에서 소리 켜기**를 누릅니다. 별도 `/game` 창을 공유하는 경우 그 창 오른쪽 아래 **소리 켜기 / 재시도**를 누릅니다. `BGM 재생 중`과 음량이 표시되는지 확인하세요. BGM ON이면 게임 시작 전에도 로컬 소리 활성화 후 재생합니다. `이 창 음소거`는 다른 송출 창이나 게임 상태를 바꾸지 않습니다. 실제 공유할 창 한 곳에서만 음향을 켜세요.

## 큰 글씨와 경쾌한 BGM
문제 64px, 보기 46px, 정답 94px를 기본으로 표시합니다. 긴 문항은 화면 밖으로 잘리지 않도록 자동 조절합니다. BGM은 120 BPM의 오리지널 연주곡으로, 북·장구 느낌의 리듬·베이스·밝은 발현음으로 구성한 32초 반복곡입니다. festival-music.cjs가 빌드 시 WAV를 생성하며 외부 음원 다운로드가 필요 없습니다. 기존 가야금 파일은 보관하지만 기본 재생에는 사용하지 않습니다.

### 이번 이동만 두 배
관리자에서 실물 주사위 1~6을 선택하고 **이동 ×2**를 켠 뒤 **주사위 공개**를 누릅니다. 6은 12칸 이동하며 송출 화면에도 계산이 표시됩니다. 이동 후 자동으로 OFF로 돌아옵니다. 점수는 두 배가 되지 않습니다.
